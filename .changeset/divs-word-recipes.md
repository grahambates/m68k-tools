Add `optimization/divs-word-power-of-two` and `optimization/divs-word-by-constant`, conditional suggestions for `divs.w #n,Dm` when only the quotient is used. The power-of-two rule suggests a plain arithmetic shift, which is smaller and much faster than `divs` but rounds differently: `divs` truncates toward zero and `asr` rounds toward minus infinity, so a negative dividend that the divisor does not divide exactly gives a result one lower (-3 / 2 is -1, but -3 >> 1 is -2). The message and the first note say so, a non-negative dividend gives exactly the same result, and the notes list the recipes that round toward zero as `divs` does (36–88 cycles against 162, using a scratch register) for when it matters. The constant rule multiplies by a reciprocal with `muls.w`, adding one to the quotient of a negative dividend, which it must do to be right at all for an exact negative multiple, and states the dividend range each recipe assumes; it also lists cheaper unsigned recipes for a dividend that is never negative. Both handle a negative divisor, since `x / -d` is `-(x / d)`: the recipe for the magnitude followed by a `neg` (and a divide by -1 is a bare `neg.w`). Both leave the remainder alone when it is provably used, need N, Z, V and C dead, and are dropped if X is read afterwards, since every recipe changes it. Recipes are generated by `scripts/generate-divide-recipes.mjs`, each checked over its range there, in a test, and against Musashi.
