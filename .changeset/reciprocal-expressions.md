`divu-word-by-constant` and `divs-word-by-constant` now write the multiplier as a fixed-point reciprocal, `ceil(scale/divisor)`, and say exactly how far it is exact. The scale is 2^16 with the shift after the `swap` chosen for the divisor (`mulu.w #6554,d0 ; swap d0` for a divide by 10 up to 16,388, `mulu.w #52429,d0 ; swap d0 ; lsr.w #3,d0` for the full 16 bits), and the range in the message and notes is the last dividend it divides exactly, found by dividing them all, where before it was rounded down to a power of two. This also covers any divisor from 3 to 65535 (32767 signed), not only those up to 300. The multiplier is written as the scale over the divisor as the source wrote it, so `divu #10,d0` gives `mulu.w #$80000/10+1,d0 ; swap d0 ; lsr.w #3,d0`, a numeric sum is kept and bracketed (`/(5*2)+1`), and a named divisor gives `mulu.w #$80000/MY_DIV+1,d0`: a number like 52429 says nothing about where it came from, this says how it was made, and with a name it follows the constant if it changes and the name is not lost. A compound divisor is bracketed (`/(MY_DIV*SCALE)+1`), and a negative one is the magnitude followed by a `neg.w`. vasm was checked to assemble each of these to the same instruction as the number. The cheaper recipes made for one particular value (a multiplier with fewer set bits, or shifts and adds) are notes only for a divisor that names nothing, since they cannot follow a constant. A divide by a named power of two still gets a shift, as `divu-word-power-of-two` does, and the name it loses is reported.
